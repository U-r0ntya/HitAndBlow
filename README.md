# ヒット＆ブロー

## 1. 目的
iOSアプリでヒット＆ブローを作成する。
また、プログラミング技術の上達も兼ねている。

## 2. 機能一覧
- CPUにランダムな3桁の数字（答え）を持たせる処理
- プレイヤーが0〜9のボタンで予想の数字を入力する機能
- 入力中の数字を1文字消す機能
- 予想を決定し、答えと比較して「hit」と「blow」の数を数える処理
- 結果（hit / blow）を表示する機能
- 予想の履歴を表示する機能
- 正解したときに、何回目で正解したかを表示する機能
- 新しいゲームを始める機能

## 3. 範囲

### 今回やること
- 2の機能一覧すべて
- 6の想定外のケースへの対応

### 今回はやらないこと
- データの保存（アプリを閉じたら履歴は消える）
- 予想回数の上限（何回でも予想できる）
- 桁数の変更（3桁固定）
- プレイヤーも数字を持ち、CPUと交互に当て合う対戦形式

## 4. 入力と出力

### 入力
- 数字ボタン（0〜9）：予想の数字を1つずつ入力する
- 削除ボタン：入力中の数字を最後の1文字だけ消す
- 決定ボタン：3桁そろった予想を確定する
- 新しいゲームボタン：答えを作り直し、履歴と回数をリセットする

### 出力
- 入力中の予想（数字を押すたびに更新）
- 決定したときの結果：「◯ヒット ◯ブロー」
- 予想の履歴：回数・予想した数字・ヒット数・ブロー数の一覧（古いものを上に表示）
- 正解したとき：「正解！ ◯回目でクリア」と、答えの数字

## 5. ルール
1. 使える数字は0〜9。答えも予想も、同じ数字を2回使わない3桁とする。
2. 先頭の桁に0を使ってもよい（例：012）。
3. アプリを開いた直後はゲームが始まっておらず、新しいゲームボタンを押すとゲームが始まる。
4. ゲーム開始時に、CPUがルール1・2を満たす答えをランダムに1つ決める。答えはプレイヤーには見えない。
5. プレイヤーは3桁の予想を入力し、決定する。
6. 予想の各桁について、答えと比べる。
   - 数字と位置の両方が一致していれば「ヒット」
   - 数字は答えに含まれているが、位置が違えば「ブロー」
   - 答えに含まれない数字は、どちらにも数えない
7. 3ヒットになったら正解でゲーム終了。それ以外なら結果を表示し、ルール5に戻る。
8. 予想を決定するたびに、回数を1増やす。

## 6. 想定外のケース

| ケース | どうするか |
|---|---|
| アプリを開いた直後（新しいゲームを押す前）に、数字・削除・決定ボタンを押す | 押せないようにする（新しいゲームボタンだけ押せる） |
| すでに入力した数字のボタンを押す | 押せないようにする（使用済みのボタンはグレーにする） |
| 3桁入力したあとに、さらに数字ボタンを押す | 無視する |
| 3桁そろっていないのに決定ボタンを押す | 押せないようにする |
| 何も入力していないのに削除ボタンを押す | 何もしない |
| 正解したあとに数字ボタンや決定ボタンを押す | 押せないようにする（新しいゲームボタンだけ押せる） |
| 前と同じ予想をもう一度決定する | そのまま受け付け、回数にも数える |
| ゲームの途中で新しいゲームボタンを押す | 答えを作り直し、入力中の数字・履歴・回数をすべてリセットする |

## 7. 完成の条件（テストケース）

### 判定（答えが 371 の場合）

| 入力（予想） | 期待する結果 |
|---|---|
| 456 | 0ヒット 0ブロー |
| 123 | 0ヒット 2ブロー |
| 713 | 0ヒット 3ブロー |
| 391 | 2ヒット 0ブロー |
| 317 | 1ヒット 2ブロー |
| 371 | 3ヒット（正解） |

### 答えの作成

| 入力 | 期待する結果 |
|---|---|
| 答えを100回作る | すべて3桁で、同じ数字が入っていない |

### 操作

| 入力 | 期待する結果 |
|---|---|
| アプリを開いた直後に数字・削除・決定を押す | 押せず、入力も履歴も空のまま |
| 1 → 1 | 2回目の1は押せず、入力は「1」のまま |
| 1 → 2 → 3 → 4 | 4は無視され、入力は「123」 |
| 1 → 2 → 削除 | 入力は「1」 |
| 何も入力せずに削除 | 何も起きず、入力は空のまま |
| 1 → 2 → 決定 | 決定できず、履歴は空のまま |
| 予想を3回決定して正解 | 「正解！ 3回目でクリア」と表示される |
| 正解後に数字・決定を押す | 押せず、入力は空、履歴は増えない |
| 同じ予想を2回決定 | 2回とも記録され、回数は2 |
| 正解後に新しいゲーム | 履歴が空になり、回数が0に戻る |
| ゲームの途中で新しいゲーム | 入力・履歴が空になり、ゲーム中の状態になる |

### テストの実行方法
- Playground の「テスト出力」の部分に、上の表を確かめるテストコードを置いている。
- 想定外のケースのテストは、結果を「OK / NG」で表示する。全部 OK なら合格。
- 「アプリを開いた直後」のテストは、`newGame()` を呼ぶ前に実行する必要があるので、必ず一番最初に置く。

## 8. 設計

![設計図](docs/design.png)

### 型

| 型 | 種類 | 中身 |
|---|---|---|
| `GameState` | enum | `.nowGame`（ゲーム中）、`.finishGame`（ゲーム前・クリア後） |
| `ThreeDigits` | struct | `first`、`second`、`third`。`digits` で `[Int]` として取り出せる |
| `GuessEntry` | struct | 1回分の記録。`digits`（予想）、`hit`、`blow` |

### データ

| データ | 型 | 初期値 | 説明 |
|---|---|---|---|
| `gameState` | `GameState` | `.finishGame` | ゲームの状態 |
| `cpuNumber` | `ThreeDigits` | `createCpuNum()` | CPU の答え |
| `inputDigits` | `[Int]` | `[]` | 入力途中の数字（最大3つ） |
| `history` | `[GuessEntry]` | `[]` | 予想の履歴 |

### 処理とデータの関係

| 処理 ＼ データ | gameState | cpuNumber | inputDigits | history |
|---|---|---|---|---|
| newGame | 書く | 書く | 書く（空にする） | 書く（空にする） |
| createCpuNum | − | − | − | − |
| pressNumber | 読む | − | 読む・書く | − |
| pressDelete | 読む | − | 読む・書く | − |
| pressDecide | 読む・書く | 読む | 読む・書く | 書く |
| displayResult | − | − | − | 読む |

- `createCpuNum` は新しい答え（`ThreeDigits`）を返すだけで、データは直接書き換えない。`cpuNumber` の初期値と、`newGame` での作り直しに使う。
- 重複しない数字は、0〜9 の候補から番号をランダムに選び、`remove(at:)` で取り出すことを3回くり返して作る。
- 回数は `history.count` で求めるので、別のデータとしては持たない。

### 画面の構成

画面を縦に 1:5:1:3 の割合で分ける。

| 割合 | 区切り | View | 中身 |
|---|---|---|---|
| 1 | CPU | `CpuSection` | CPU の番号（ゲーム中は隠し、クリアしたら表示） |
| 5 | 履歴 | `GameSection` | 予想の履歴（`HistoryRow` を並べる。古いものを上に表示） |
| 1 | 入力中の数字 | `MyNumberSection` | 入力中の3桁（未入力の桁は「-」） |
| 3 | ボタン | `ControlSection` | 数字ボタン（`NumberButton`）、決定（`DecideButton`）、削除（`DeleteButton`） |

- ニューゲームボタンは、ナビゲーションバーの右上に置く。
- 割合は親の `HitAndBlowScreen` で決め、各区切りの中身は Section / Component のファイルに分ける。

## メモ
- 「ゲーム説明」にあった「プレイヤーとCPUが一対一で対戦する」は、CPUの答えをプレイヤーが当てる一方通行の形にした。お互いに当て合う形式は「今回はやらないこと」に入れた。
- 6の対応（使用済みのボタンを押せなくする、など）は仮で決めたもの。エラーメッセージを出す形にしたくなったら変更する。「グレーにする」などの見た目はフェーズ4で対応し、フェーズ2では「押しても入力が増えない」ことだけを確かめた。
- 履歴の並び順は、古いものを上に表示する（わざとこの順にしている）。
- アプリを開いた直後は、新しいゲームボタンを押すまで遊べない形にした（gameState の初期値が .finishGame のため）。
- 答えとの比較は、今回は独立した関数にせず pressDecide の中で行う。テストするときは、Playground で cpuNumber に答え（例：371）を直接入れてから pressDecide を呼んで確かめる。
- 変数名は、設計時の `cpuNum` から、コードでは `cpuNumber` に変更した。
